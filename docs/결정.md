### CC-1. 링크 재실측 반영 완료 — **보고서 두 곳이 바뀝니다** 🔴

요청하신 대로 `l3=110`, `l4=135` 반영, MJCF 재생성, `validate_mjcf.py` **8/8 재통과**.
FK 대조는 여전히 0.0000mm 입니다. 그런데 파급이 요청 범위보다 컸습니다.

**① 보고서의 몸통 높이를 `110mm` → `95mm` 로 고쳐야 합니다.**

`height` 는 "Upper축~발 = 120+height" 를 명령하는 값이라 링크 길이와 무관합니다.
그런데 다리 도달이 263 → 245mm 로 줄면서 **같은 명령이 훨씬 뻗은 자세**가 됩니다.

```
height 110 명령  ->  H 230mm 요구  ->  도달 245 의 94%  ->  특이점 근처
                     무릎 슬루 516도/s (정격 95%)
```

**로봇은 거기 있던 적이 없습니다.** 옛 코드가 다리를 길다고 믿어 명령한 각도를
진짜 다리에 넣으면 실제로는 H **214.5mm** 로 섭니다 — 새 코드의 `height 95` 입니다.
8/20 에 걸은 것이 그 자세입니다. 기본값을 95 로, 상한을 105 로 내렸습니다
(상한은 도달 한계 125 가 아니라 슬루가 정합니다).

> 보고서 설정 표: `몸통높이 110mm` → **`95mm`**. 같은 숫자가 아니라 같은 자세입니다.

**② "미끄러짐 0" 은 아직 성립하지 않습니다. COO 지적이 맞았습니다.**

옛 모델의 명령 각도를 실제 다리에 통과시켜 실제 발끝 이동을 계산했습니다.

| | |
|---|---|
| 명령 보폭 | 70mm |
| **실제 발끝 이동** | **65.3mm** (COO 추정 65.2 와 0.1mm 차이) |
| 실제 속도 | 46.6 mm/s |
| 1m 소요 | **21.4초** (기록 "20초") |

1.4초 차이는 "약 20초" 에 묻힙니다. 화요일에 **스톱워치로 두 번** 재면 결판납니다
(앱 우측 하단에 스톱워치 넣었습니다. 전진/후진에 시작, 탭하면 0 부터).

> **보고서 반영 제안**: 확정 전까지 *"이론값과 측정 해상도 안에서 일치. 미끄러짐은
> 유의미하게 관측되지 않음"* 정도로. `0.05 m/s` 도 `0.047~0.050` 로 폭을 두거나
> 재측정 후 확정. 어느 쪽이든 2차 기능테스트에서 그대로 확인됩니다.

> **COO 답변 (CC-1)**: 둘 다 반영했습니다.
> - 설정 표 `몸통높이 110mm` → **`95mm` (조절 범위 60~105)**
> - 전진 속도 `0.05` → **`0.047 ~ 0.050 m/s`**
> - "실측 100%, 미끄러짐 0" → **"측정 해상도 안에서 일치, 미끄러짐은 유의미하게

### CB-9. 🔴 `pyproject.toml` 에 **GPL-2.0-only 의존성**이 들어 있습니다 — 라이선스 검증 위험
**기한 8/22 · CTO 소유 파일(`oss_spotmicro/main`) 이라 COO 가 손대지 않았습니다**

**대회에 라이선스 자동검증 단계가 있습니다.** 2차 평가 기간(10/12~10/28)에 "출품작 검증 — 기능테스트, 라이선스 검증(온라인 검증 툴로 라이선스 충돌·위반 확인)" 이 돌아갑니다.

현재 `oss_spotmicro/main/pyproject.toml`:

```toml
dependencies = [
    "gymnasium>=1.2.3",
    "mujoco>=3.4.0",
    "robot-descriptions>=1.22.0",
    "stable-baselines3[extra]>=2.7.1",   # ← 여기
    "tensorboard>=2.20.0",
]
```

`stable-baselines3` 의 `extra` 구성을 메타데이터로 확인했습니다.

```
opencv-python · pygame-ce · tensorboard · psutil · tqdm · rich
ale-py>=0.9.0 ; extra == "extra"      ← 문제
pillow · pandas · matplotlib
```

**`ale-py` 의 라이선스는 `GPL-2.0-only` 입니다** (설치본 메타데이터로 확인). 우리 저장소는 **GPL-3.0-or-later** 이고, GPL-2.0-**only** 는 GPL-3.0 과 **비호환**입니다. 검증 툴이 이 조합을 충돌로 잡을 가능성이 높습니다.

그리고 **우리 코드는 `ale-py` 를 전혀 쓰지 않습니다.** `rl/` 전체의 실제 import 를 뽑아 봤습니다.

```
argparse  Common  gymnasium  imageio  itertools  Kinematics  math
mujoco  numpy  os  pathlib  rl  stable_baselines3  sys  time
```

`imageio` 는 `rl/render_gait.py:64` 한 곳뿐이고, `opencv`·`pygame`·`ale-py`·`robot-descriptions` 는 어디서도 쓰지 않습니다.

**제안 패치**

```toml
dependencies = [
    "gymnasium>=1.2.3",
    "mujoco>=3.4.0",
    "stable-baselines3>=2.7.1",     # [extra] 제거 — ale-py(GPL-2.0-only) 가 딸려온다
    "tensorboard>=2.20.0",          # extra 로 오던 것을 명시적으로
    "imageio[ffmpeg]>=2.37",        # rl/render_gait.py
    "numpy>=2.0",
]
# robot-descriptions 제거 — 미사용
```

**추가로 torch CPU 빌드 고정을 제안합니다.** 현재 `.venv` 에 `nvidia-cublas`·`cudnn`·`nccl`·`triton` 등 CUDA 패키지가 20여 개 깔려 있는데, README 와 보고서가 "GPU 불필요"를 핵심 주장으로 내세우므로 **붙임1 SBOM 에 CUDA 스택이 올라가면 메시지가 정면으로 상충합니다.**

```toml
[tool.uv.sources]
torch = { index = "pytorch-cpu" }

[[tool.uv.index]]
name = "pytorch-cpu"
url = "https://download.pytorch.org/whl/cpu"
explicit = true
```

**부수 효과**: 붙임1 SBOM 이 짧고 깨끗해지고, `uv export` 로 자동 생성할 수 있게 됩니다. `NOTICE` 5장의 "모두 GPL-3.0 과 호환" 문장도 이 패치 후에야 사실이 됩니다 (지금은 부정확).

> 참고: `description = "Add your description here"` 가 기본값 그대로입니다. 제출물이므로 채우는 편이 좋겠습니다.

### CB-8. 학습이 성립하지 않던 원인 — 보고서 재료입니다 (회신 불필요, 공유)

**오진할 뻔한 것** — "기립 자세가 다리 도달의 88%까지 뻗어 있어 불안정하다"

| 조건 | 300스텝 중 생존 |

| 랜덤화 OFF · 행동 ±0.25 | 300 (완주) |

음의 항  -2.75 /스텝   (ang_vel_xy -0.93, undesired -0.78, orientation -0.34 …)
────────────────────────
순       -2.40 /스텝

에피소드가 끝나면 페널티도 멈춥니다. 순보상이 음수면 **정책 입장에서 최적 전략이

| 초기 std | 생존 | 순보상/스텝 |
|---|---|---|
| 1.00 (기본) | 25 | **−2.40** |
| 0.37 | 39 | −1.27 |
| **0.135** | **515** | **+0.27** ← 부호가 뒤집힘 |
| 0.05 | 660 | +1.24 (탐색이 좁아 보행 미발견 위험) |

**보고서에 쓸 문장** — "보상 항목의 가중치가 아니라 **합의 부호**가 문제였다.

```
대각 지지선   -25.0mm
무게중심      -36.4mm    <- 11.4mm 뒤
```

트롯은 주기의 일부를 대각선 두 발로만 버티고 그때 지지면은 '선'이다. 무게중심이
그 선보다 뒤에 있으면 뒤로 넘어간다. 피치 트림이 그것을 상쇄하고 있었다.

직접 방아쇠는 **스윙비율을 올린 것**으로 보입니다. `네발지지 = 1 - 2 × 스윙비율`:

| 스윙비율 | 네발지지 | |
|---:|---:|---|
| 0.143 | 71% | 기본값 |
| **0.21** | **58%** | **8/20 넘어짐** |
| 0.25 | 50% | work11 §6.16.1 주저앉음 |

**경고 임계값을 실측에 맞춰 고쳤습니다** — 50% 미만에서만 주황이던 것을
65% 미만 주황 / 55% 미만 빨강으로. 스윙비율 0.175 초과 시 경고 문구도 띄웁니다.

> **로봇은 자기가 넘어진 것을 모릅니다.** IMU 가 없어 쓰러진 채로 보행 명령을
> 계속 냅니다. 로그에도 넘어짐이 남지 않습니다. 이것이 IMU 가 강화학습 이식의
> 전제인 이유이고, 보고서 한계점에 들어갈 항목입니다.

**무릎 혼 4개 체결 확인이 이제 선택이 아닙니다.** 하루에 정격 초과 2회(최대 703°/s)에
낙하 충격까지 겹쳤습니다. work11 §6.13 에서 혼이 이탈한 전례가 있습니다.
